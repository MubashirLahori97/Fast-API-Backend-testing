# Genesis Health Backend API

FastAPI backend for "Your Oracle Clinician" (Genesis Health), serving a mobile app and a web app.

Scope: the Client user stories (`docs/requirements/client-user-stories.md`) and the Admin and Super Admin stories (`admin-user-stories.md`, `super-admin-user-stories.md`, Phase A). The build order, design decisions, assumed values and each story's definition of done are in `docs/PLAN.md`; tick stories off there as they're finished. On 6 Nov every phase's code was built first, with no new tests (PLAN's "Build status"): each part's decisions, messages and open questions are in `docs/decisions/*.md`, and tests and reviews come next.

## Commands

Python 3.12 and dependencies are managed with [uv](https://docs.astral.sh/uv/); Postgres runs in Docker. Run everything from the repo root.

```bash
cp .env.example .env               # first time only
docker compose up -d               # Postgres on host port 5433, and the test inbox (Mailpit) at http://localhost:8025
uv sync                            # build .venv from uv.lock
uv run alembic upgrade head        # apply migrations
uv run fastapi dev app/main.py     # API with auto-reload; Swagger UI at http://127.0.0.1:8000/docs
uv run python -m app.worker        # background job runner, in its own terminal
```

- Tests (need the Docker database): `uv run pytest`. One file: `uv run pytest tests/test_jobs.py`. One test: `uv run pytest tests/test_jobs.py::test_failed_job_is_retried_later`.
- Lint and format: `uv run ruff check --fix .` and `uv run ruff format .` (line length 100).
- After changing models: `uv run alembic revision --autogenerate -m "add sessions"`, then read the generated file in `migrations/versions/` before applying it. Autogenerate misses triggers, functions and data changes.
- Add a dependency: `uv add <package>` (`uv add --dev <package>` for tools); commit `pyproject.toml` and `uv.lock` together.
- SQL shell: `docker compose exec db psql -U genesis -d genesis_health`

## Architecture

- `app/main.py` creates the app, adds CORS and the error handlers, and mounts the routers under `/api/v1` (`/docs` and `/openapi.json` stay at the root). Paths in docs and tests are written without the prefix; the test client's `base_url` adds it. Each domain package (`app/auth/` now; `profiles/`, `conversations/` and the rest are added in their phase of `docs/PLAN.md`) holds `router.py`, `schemas.py`, `models.py` and `service.py`. Keep routers thin and put business rules in `service.py`.
- `app/core/`:
  - `config.py`: `settings`, read from environment variables and then `.env`. Durations, limits and other tunable values go here.
  - `database.py`: the engine (with `hide_parameters=True`, which keeps query values out of errors and logs), `Base` (every datetime column is `timestamptz`; tables use UUID primary keys), and `DbSession`, the per-request session dependency.
  - `errors.py`: every error response is `{"error": {"code", "message", "field"}}`, and validation errors add `details`. Raise `AppError(status, code, message, field)` for errors the apps should show; pass `details=[...]` when there's more than one problem. Messages raised in Pydantic validators pass through without the "Value error, " prefix, so validators should use the stories' exact wording.
  - `zip_codes.py`: `zip_in_state(zip_code, state)`, from each state's USPS ZIP prefixes. Sign-up and Profile & Account check every ZIP code with it.
  - `ages.py`: `age_on`, `today` (the UTC date), `age_of_majority(state)` (18, or the state's own from `settings.age_of_majority_by_state`: 19 in AL and NE, 21 in MS), and `is_adult(dob, state)` / `age_group(dob, state)`, which count on Hawaii's date. A family member uses the account holder's state (`Profile.majority_state`). Work out every age with these.
  - `audit.py`: `audit.record(db, action, ...)` adds an audit event, saved when the caller commits. `client_ip(request)` is the address it stores (an IPv6 address as its /64); per-IP limits must count with the same function. The database rejects UPDATE, DELETE and TRUNCATE on `audit_events`. Events must never hold health data, passwords, codes or tokens.
  - `email.py`: the `EmailSender` protocol and the `get_email_sender` dependency, which prints to the console in dev (or, with `EMAIL_BACKEND=smtp`, sends to the local Mailpit inbox from `compose.yaml`) and refuses to run when `ENVIRONMENT=production`. Endpoints take `EmailLater`, a `send(message)` callable that sends after the response (background task), and pass it to services. Tests use `InMemoryEmailSender`; background tasks finish before `TestClient` returns.
  - `jobs.py` with `app/worker.py`: `enqueue(db, kind, payload, run_at)` adds a row to `jobs`. The worker claims due rows with `FOR UPDATE SKIP LOCKED`, runs the handler registered with `@handles(kind)`, and retries a failure up to 5 times. Handler modules are imported in `load_handlers()` in `app/worker.py`. Payloads carry ids, never health data.
- `app/auth/` handles sign-up, sign-in, 2FA, sessions and passwords. Sign-up saves the form as a `PendingSignUp` (one per attempt, even for the same email, so nobody can block someone else's sign-up) and emails a code; the account is created only when `POST /auth/verify` gets that code, and takes the attempt's id. Unverified attempts are deleted by the `auth.purge_pending_sign_up` job (`app/auth/jobs.py`); `users.email_verified_at` is always set. A code whose attempt is gone keeps no owner and only answers "request a new code". The sign-in flow is `POST /auth/signin`, which returns `signed_in` on a trusted device or `verification_required` with a code emailed, then `POST /auth/verify`, which returns an access token plus a `device_token` the app keeps for its next sign-in. Sessions, trusted devices, codes and reset tokens are stored only as SHA-256 hashes (`security.hash_secret`); passwords use Argon2id. Rows with counters or single-use state are read with `FOR UPDATE`, and per-IP and per-account limits count recent rows in `audit_events`. The limits are listed in `docs/PLAN.md` under the Phase 1 and R1 decisions. Each session and trusted device has a `platform`: `web` (12 hours at most, 30 minutes idle) or `mobile` (up to 30 days, no idle timeout), chosen by `service._platform`, which gives browsers `web` whatever they declare. Signed-in endpoints take `CurrentSession` from `app/auth/dependencies.py`, which enforces revocation (keeping the timeout or deactivated message via `revoked_reason`), the maximum age and the web inactivity timeout; `session.user` is the client.
- `app/accounts/` holds policy versions and acceptances, `/me`, `/me/next-step` (the screen to show after sign-in) and `/me/password`. Its `ClientSession` dependency is the policy gate: a signed-in session whose client has accepted the current policies (403 `policy_update_required` otherwise). Every profile and health endpoint uses `ClientSession`; only the endpoints a client needs in order to accept policies use plain `CurrentSession`.
- `app/profiles/` holds profiles (the client's own and their family members'), the guided health intake and Manage Family. Endpoints that take a profile use `OwnedProfile` from `app/profiles/dependencies.py`, which loads `{profile_id}` and returns 404 unless it belongs to the signed-in account. Never load a profile by id any other way.
  - A profile is the client's own (`is_self`) or a family member's. Each kind has its own intake questions (`SELF_QUESTIONS`, `FAMILY_QUESTIONS` in `schemas.py`).
  - A finished family member can be turned off (`turned_off_at`: hidden from the profile panel, can't be used, doesn't take a plan place). They can also have a pending deletion request (`deletion_requested_at`, plus a row in `DeletionRequest` in `app/accounts/models.py`). Anything that uses a profile, such as conversations, must refuse both.
  - `default_profile` is the profile to open after sign-in and to fall back to.
- `app/oracle/` is the only way the backend talks to the AI team's service. `contract.py` defines the calls (`check_safety`, `stream_reply`, `topic`) and what each one is given: `ProfileContext`, picked field by field, and `SafetyContext`, the minimum before the Health Consent. `get_oracle` returns `FakeOracle`, or with `ORACLE_BACKEND=senior` the `SeniorChatOracle` (`senior.py`), whose replies come from the senior team's chat API (`POST /api/v1/chat/stream`) while every other call is still the fake. It refuses to run in production, because the safety check is still the fake (`docs/decisions/senior-chat-oracle.md`). Everything passed to the Oracle is health data. Oracle failures are logged by class name only.
- `app/conversations/` holds conversations, messages and the per-profile Health Consent (story 3.1).
  - Sending saves the client message first, with a `conversations.safety_check` job (`app/conversations/jobs.py`). Then it runs the safety check with no lock or transaction held; the job retries it if it failed.
  - `POST /conversations/{id}/reply` streams the reply as server-sent events from a sync generator. The router iterates and closes it in the thread pool, and it uses the request's session, which FastAPI closes only after the stream ends.
  - Profile-scoped endpoints take `UsableProfile`; conversation endpoints take `OwnedConversation` and check the profile themselves.
  - A deleted conversation keeps its rows with `deleted_at` set until Phase 10's purge. `OwnedConversation` answers 404 for it, and every query that lists conversations or gives them to the Oracle must filter `deleted_at IS NULL`.
  - `MessageFeedback` holds a thumbs up or down per Oracle message; its comment is health data.
  - Rate limits, the reply claim and the time limits are settings.
- Polling endpoints (unread counts, the admin dashboard's refresh) take `BackgroundSession`, `ClientBackgroundSession` or `AdminBackgroundSession`: the same checks, but the request doesn't count as activity, so an unused web tab still times out. `ClientSession` refuses accounts whose role isn't `client` (403 `clients_only`), so no health data can be stored on an admin account.
- `app/billing/` holds subscriptions (stories 9.1 and 11.3). `catalog.py` is the one place plans and prices are read: the Super Admin's `billing_plans` rows, falling back to the settings for a launch plan with no row, cached per process (`refresh(db)`, `clear_cache()`). `provider.py` is the `PaymentProvider` protocol; `get_payment_provider` returns `StripeProvider` (`stripe_provider.py`) when `STRIPE_SECRET_KEY` is set, otherwise the fake in development and test, and refuses to run in production without the Stripe secrets. Tests always get the fake (`tests/conftest.py` blanks the key). Stripe setup: `docs/decisions/stripe-billing.md` and `scripts/create_stripe_prices.py`. `entitlements.py` says what the account may use: `feature_access` and `check_feature` (the trial locks most features), `trial_days_left`, and the family places. Check family places with `check_can_add_family_member` and `check_can_turn_on_family_member`, under the account row lock, rather than reading `users.subscription_plan` (a copy of the subscription's plan) directly. `family.py` turns family members off and back on when the plan changes.
- `app/health/` is the health profile (story 6.1): the question bank in `questions.json`, rebuilt from the BA's Health Intake Routing document (`docs/decisions/phase-4-routing-doc.md`), with its `show_if` routing and each question's `when_asked`, the answers, and the Hypothalamus Circle Map (placeholder until Deborah's map arrives). Details the Oracle picks up in conversations are saved straight away ("Added from our conversation"); only a logged visit's changes wait as pending facts for the client to confirm.
- `app/guidance/` holds guidance summaries (3.3) and provider-ready notes with their versions (3.4, 3.5), and their PDFs (fpdf2). `app/visits/` holds visit logs (5.2) and the combined visit notes list and search (5.1). `app/wellness/` is the Wellness Plan (7.1): the plan, its items and versions, updated after a full summary, a logged visit or a health profile change. Its protocols library reads published knowledge base content (`protocols.json` holds only the tabs and sections). Everything these give the Oracle goes through `ProfileContext`, which `conversations.service.profile_context(..., db)` fills.
- `app/notifications/` is 12.1 and 12.2: `notify` (in-app, push and email, by the client's preferences), `schedule` and `cancel_scheduled` for reminders, the kinds in `kinds.py`, push tokens, and a reminder sweep the worker starts. `app/core/push.py` is the push sender, like `email.py`.
- `app/support/` holds support requests (10.1); `app/privacy/` holds Export My Data, revoking consent, and deletion requests with their 10-day grace period, lock, 45-day deadline and purge (11.4, 8.2).
- `app/teens/` is teens with their own account (1.5, 1.6): `users.account_type` is `adult` or `teen`, `teen_links` is the parent's side of an invite, and `access.py` is the gate that pauses a teen when the parent's Family plan, consent or Health Consent lapses.
- `app/dashboard/` is the Home Dashboard (4.1): one read-only endpoint per profile, built from the other packages' functions.
- `app/admin/` is the admin panel (Phase A). Its endpoints take `AdminSession` or `SuperAdminSession` from `app/admin/dependencies.py`; a client's token gets 404. Admins always sign in with a code and are signed out after 15 idle minutes. `notify_admins` (`app/admin/notifications/`) alerts the team. `app/knowledge/` is the knowledge base the Oracle answers from, with knowledge gaps. The one Super Admin is created with `scripts/create_super_admin.py`.
- `app/models.py` imports every models module so `Base.metadata`, and therefore Alembic, sees all tables. Add new models modules there.
- `migrations/` is Alembic. `env.py` takes the URL from `settings`; the tests pass their own through `config.attributes`. New migrations are named by date and are linted and formatted by ruff automatically.
- `tests/conftest.py` drops and recreates `<dev database>_test` at the start of each run and migrates it from empty. Each test runs in a transaction that's rolled back afterwards, even if the code under test commits. Fixtures: `db`, `client` (a `TestClient` with `get_db`, `get_email_sender` and `get_oracle` overridden), `email_sender`, `oracle` (the `FakeOracle` in use: set `reply`, `widgets`, `safety`, `fail_safety` or `fail_after`; `calls` and `last_*` show what it was asked), `make_user(...)` (a verified client who has accepted the current policies and finished their own intake; pass `intake_done=False` for a brand-new client) and `sign_in(...)` (signs in through the API, entering the emailed code if asked). `tests/helpers.py` has `PASSWORD`, `last_code`, `last_reset_token` and `bearer`. `tests/test_migrations.py` fails when a model changes without a migration. Test files are named after the story they cover, and their docstrings name it.
- `compose.yaml` runs `pgvector/pgvector:pg16` on `127.0.0.1:5433`. The pgvector extension has to be enabled with `CREATE EXTENSION vector` in a migration when it's first needed.

## Conventions

- Look stories up by title, not number: many "see story X.Y" links in the requirements use old numbers. Open questions for the BA are tracked in `docs/PLAN.md`. Where a story is unclear, follow `docs/PLAN.md` and record the assumption there.
- Messages the apps show use the stories' exact wording, including the typographic apostrophe (’). Where a story has no message, or the stories conflict, record the choice in `docs/PLAN.md`.
- Health data (PHI) never goes into logs, URLs, error messages, audit events, job payloads, or push and email text.
- Every endpoint that takes a profile or record id checks that it belongs to the signed-in account.
- `.env` is gitignored. `.env.example` holds the local-only values that match `compose.yaml`; a new setting goes in both.
